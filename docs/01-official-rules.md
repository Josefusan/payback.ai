## 4. How To Enter

Visit paypalaihackathon.devpost.com ("Hackathon Website") and:

1. Register by clicking **"Join Hackathon"**; sign up for or log in to a free Devpost account.
2. Obtain access to the required developer tools/platform and complete a Project (below). Use of developer tools is subject to their license agreements. Entry = consent for Sponsor and Devpost to collect and maintain entrant personal info to operate and publicize the Hackathon.
3. For the PayPal sandbox, use an existing PayPal account or create a free account at https://developer.paypal.com/.
4. Complete all required fields on the **"Enter a Submission"** page during the Submission Period.

### Project Requirements

- **What to Create:** build or update an application that integrates the **PayPal developer platform (using the free sandbox environment)** along with **an AI tool, model, or platform** of the entrant's choice (a "Project").
  - Includes all PayPal services: Venmo, Braintree, Xoom, Honey, Zettle, Paidy, Hyperwallet, Simility, Swift Financial, and others.
  - PayPal provides access to select AI sponsor tools (optional): **AG Grid, APIMatic, Astropods, Bryntum, Channel3, Elastic, KERNEL, Postman, Render, Zapier.** "Any AI tool works, as long as **PayPal integration is central** to the project."
- **Sponsor Prizes:** projects submitted for Sponsor Prizes must also follow the specific requirements in §8.
- **Functionality:** must install and run consistently on its intended platform and **function as depicted in the video and/or text description**.
- **Platforms:** must run on the platform for which it is intended and which is specified in the Submission Requirements.
- **New & Existing:** newly created, or if it existed before the Submission Period, **significantly updated after the period started** — entrants should explain how. Sponsor/Administrator decide what is "significant" at their sole discretion.
- **Third Party Integrations:** entrant must be authorized to use any third-party SDK, APIs, and/or data under their terms/licenses.

### Submission Requirements

1. A Project built with the required developer tools meeting the Project Requirements.
2. A **text description** explaining features and functionality.
3. **Access to a functional demo.** The project need not be publicly hosted, but **judges must be able to actually run or interact with a working build**, via either:
   - clear, complete **setup and run instructions** in the code repository, OR
   - a **hosted demo URL**.
   - A design mockup, static prototype, or non-functional demo **does not** meet this requirement.
4. A URL to a **public code repository on GitHub**:
   - containing all source code, assets, and instructions needed for the project to be functional;
   - **public and open source**, with an **open source license file** detectable and visible at the top of the repo page (About section).
5. A **demonstration video**:
   - **less than three (3) minutes** (judges need not watch beyond 3:00);
   - shows the Project **functioning on the device for which it was built**;
   - uploaded to **YouTube**, **publicly visible**, link provided on the submission form;
   - **no third-party trademarks, copyrighted music, or other material** without permission.

## 6. Judges & Criteria

Sponsor and Administrator choose eligibility and judging methodologies, which **may include expert panels, peer review, automated AI-driven analysis, or any combination**. Judges selected by Sponsor; may be Sponsor employees or third parties; may change. One or more rounds/panels.

**Stage One (pass/fail):** baseline viability — the Project **reasonably fits the theme** and **reasonably applies the required APIs/SDKs**.

**Stage Two (equally weighted):**

1. **Technological Implementation** — How thoroughly and skillfully does the project use PayPal Developer Platform and AI tool(s)? Does it reflect genuine effort and a working, non-trivial implementation?
2. **Design** — Does it deliver a complete, coherent product experience — not just a technical proof of concept?
3. **Potential Impact** — Does it make a credible, specific case for solving a real problem for a real audience — and does the solution actually address that problem based on what's demonstrated?
4. **Innovation/Idea** — How creative and novel is the concept, and does it differ from existing concepts?
5. **Presentation** — Does the video clearly demonstrate the project working end-to-end? Does the pitch communicate what problem is solved, who it's for, and why it matters? Is it easy to follow?

**Tie breaking:** highest score on the first applicable criterion in the order above (Technological Implementation first), then the next, etc.; if tied on all, Judges vote.
